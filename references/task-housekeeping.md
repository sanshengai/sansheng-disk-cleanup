# 让产生文件的 Agent 负责收尾

此能力有两个入口：用户说“清理本对话 / 阶段收尾”时，先做本任务盘点，不启动全盘扫描；用户要求“减少以后积累 / 学会我的习惯”时，整理稳定边界建议。全盘扫描是发现遗漏和纠正错误的兜底。

## 三层信息，各归其位

1. **共性习惯**：任务开始选定过程目录；默认引用现存素材；需要独立副本时优先工具的写时复制；生成器用 `TemporaryDirectory` / `finally` 清自己的暂存；阶段完成或交接前主动盘点。不能要求等用户说“清理”才收尾，也不依赖不可靠的“对话关闭”事件。
2. **用户边界**：哪些原始资料长期保留，成品去哪里，哪些私有备份才算合格，是否允许清理、回滚保留多久。按真实工作需要设置，不按职业标签推断。视频用户可能要原镜头和声音工程；编程用户可能要测试失败证据和续跑点；日常工作用户可能要原文与审批链。
3. **任务账本**：具体文件归属、输入和输出关系、修改前是否存在、交付与备份证据。放任务记录中，不把每次扫描的路径、大小、失败日志塞进全局记忆。

三者都不替代内容校验、引用与进程检查，不构成新的删除权限。Skill 是按需读取的操作手册，不会仅因更新而让所有 Agent 自动加载。需要常驻提醒时才将下面的短规则安装到用户现有共享规则真源。

## 原 Agent 的阶段收尾

先使用当前上下文、工具调用与任务记录回答：本阶段新建了什么、修改了什么、谁仍在消费、成功或失败的证据是什么。当前目录、文件作者、名称中的任务号和“我记得”都不能单独证明归属。

- 开始：记录 task_id、工作根和本阶段用途；只为明确要产出的文件记录精确路径与“创建前不存在”证据，不为此扫描整盘。已有共享目录不得标成本任务独占。
- 运行：输入尽量按路径引用，不反复复制全量库。临时生成直接放工具管理的独占暂存目录；正常退出和异常退出都清理该目录。长任务需要续跑时，暂存变为显式检查点，写用途、消费者和下次复核点。
- 阶段完成、失败放弃或交接：将账本逐项分为保留输入、正式成果、必要检查点、无消费者的过程件、归属不明。成品已上传不能证明原始素材也已备份；失败现场有诊断价值时保留最小复现及日志。
- 执行：本轮已有清理授权继续有效；普通第三方清理仍走 `plan.py` / `act.py`，不因自称“自己生成”跳过 24 小时、引用或保护。当前任务的即时清理优先依靠**创建时就设定生命周期的工具暂存机制**，不能临时把整个工作目录当作暂存并递归删掉。尚未具备归属或执行证据的，记录具体保留原因和后续动作。
- 交付：说明已清理的对象与实测、仍保留的检查点及原因、下一阶段必须读的文件。不得把“写了收尾计划”说成已经清理。

账本可使用 [templates/task-artifacts.json](../templates/task-artifacts.json)。这是证据交换模板，**不是删除脚本输入**。字段不完整就保持 unknown；创建时记录的状态与结束时哈希都要保留。不要补造历史“创建前不存在”的证明。

## 扫描如何学到习惯

每次只处理新增证据和已确认边界的冲突，避免反复问用户同一问题：

1. **观察**：例如“某生成器每次复制整套字体”“验收页把视频再次内嵌”。记产生者、任务、频次、体积及证据来源；只能称观察，不能推成用户偏好。
2. **解释与方案**：判断是否必要，优先修生成器生命周期、共享引用、精简验收页，而非增加一个定时删目录的任务。
3. **待确认边界**：把确实需要用户取舍的规则写成短句，列适用对象、条件、例外、后果。用户先前已经确认的边界直接复用，不重复询问；新规则先展示再保存。
4. **保存与核验**：事实身份卡用 `memory.py identity`；本 Skill 的备注或规则按 `memory.py pending` → 用户确认流程。跨 Agent 的常驻规则写用户已有共享真源，不碰原生记忆数据库、不复制四份规则。记录修改前版本与回滚方式，核对各 Agent 入口；新会话实际加载后才算验证，不把 symlink 存在说成已加载。
5. **下轮反馈**：复查该来源是否还增长、是否真的执行了收尾。边界有误或用户改主意时更新同一条并撤销旧条，不无限追加。空间充足不等于已治理；空间上涨也不等于全是垃圾。

默认不装后台任务。脚本/生成器自动清自己的短命暂存，与全盘常驻清理是两件事。

## 可审阅的常驻短规则

以下是安装候选，不是要求自动改用户配置。若用户已明确授权安装这些内容，按已有授权执行，不再确认。

> 每个任务对自己产生的过程资料负责：开始时选定过程目录并记录新建文件归属，运行中优先引用已有输入，工具暂存设定退出清理；阶段完成、交接或放弃前主动盘点本任务产物。在现有授权与保护规则内清理明确无后续消费者的过程件，保留成品、原始素材、必要续跑点和唯一证据，报告未清理项的具体原因。不得清理别的会话现场，不以“已上线”“可再生”或时间旧作为唯一依据。个人保留边界读已确认的用户配置；需要第三方复核时调用清理 Skill。

用户特有的存放位置、敏感项目、保留期限放私有配置中，不写进公开 Skill 或公开模板。
