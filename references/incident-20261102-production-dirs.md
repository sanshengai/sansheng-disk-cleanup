# 事故复盘：2026-11-02 误删视频生产目录

## 经过
- 2026-11-02 07:23–07:25，清理把一条视频产品线成品目录下的三个目录先打 tar 再删除，理由是“旧试做版本”：
  - `试做三集-<日期>`（5.9G）
  - `第一集写实重制-<日期>`（3.8G）
  - `新版顺序生产-v3-<日期>`（2.4G）
- 它们没有进程在用、没有 git 改动，但其实是视频流水线**正在用的生产素材**：被制作台账（sqlite）、交接文档、`AGENTS.md` 引用，后续集数会复用（音乐库、角色形象、配音素材等）。
- 负责视频制作的 Agent（Claude Code）发现目录不见了，查不到原因——清理没有在任何 Agent 会去看的地方留日志。
- 另一个 Agent 从网盘备份和同盘存档恢复。

## 根因
1. “在用”判断只看了进程、打开文件、git 状态和最近写入；没查台账/文档/其他项目的引用。
2. 没查备份状态；同盘存档被当成“安全”。
3. 名字里有“试做/重制/v3”被当成可删依据；人做的成品素材和可再生缓存用了同一套放行标准。
4. 删除没有隔离期，也没有统一日志和恢复命令。

## 改进（已写入 SKILL.md「防误删红线」，triage.py 已实现 1、2、4 的只读检查）
见 SKILL.md。核心一句：**人做的东西默认不删；被引用就问；同盘存档不算备份；先改名隔离 7 天；每次删都记日志并告诉用户恢复命令。**
