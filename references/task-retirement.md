# 任务退役调查：找出失去用途的执行现场

适用：用户认为 Agent 留下大量已无后续用途的过程资料，或扫描显示旧任务目录、临时源码检出、批量登记暂存、子 Agent 历史占大头。先复用本轮清单，按收益下钻；没有新证据时不重复全盘扫描。

## 以任务阶段为清理单元

把大目录按任务、阶段、实际生产器归组，汇总许多小文件。记录任务归属、文件角色、交付/放弃证据、续跑入口、输入与输出、当前消费者和名义体积。目录后缀日期不等于最后运行时间；以回执和实际文件变化交叉核实。

每组收敛到一种处理结论，范围内混有不同结论就拆成互斥文件集合：

| 结论 | 应给出的证据与下一步 |
|---|---|
| 推荐删除 | 已结束子阶段、无有效消费者、精确文件范围及保留依据；进入既有清理校验，已有授权覆盖就继续执行 |
| 保持路径去重 | 哪些消费者仍需各自路径、完整内容哈希相同、现有执行器是否覆盖；保留路径和独立编辑能力，按既有流程试点 |
| 明确保留 | 当前输入、唯一成果、必要续跑点或回滚用途的具体证据，以及占用量 |
| 具体缺口 | 尚缺哪条交付、消费者、备份或归属证据，查什么可解决；确需用户判断时只问任务意图，不让用户代查文件 |

这是调查结论，不是替代 `verdict` 或新增授权。不能用“都留着”结束调查，也不为等待证据不足的一组而搁置已获授权的成熟候选。整项目未完不代表其中每次试验、登记或构建阶段都必须保留；单阶段 PASS 也不代表整个项目已交付。

调查顺序由实际体积决定，通常包括整仓复制、构建/派生快照、登记阶段的重复全库、迭代媒体、批量生成试稿、会话和子会话历史。将同内容副本、唯一过程件和最终成果分开计量；不能把去重总量当作实际可释放量。

## 从大头识别产生机制

复用已有清单，只对对应子任务下钻；以下是调查线索，不是固定可删除目录：

| 现象 | 追查什么 | 可形成的处理范围 |
|---|---|---|
| 每批只增加少量实体，却新增成千上万份 JSON | 比较 stage 与正式 manifest 的成员及哈希，追到实际调用的生产器是否每次复制全库；核验完成回执覆盖范围 | 已完成阶段中与正式实体一致的副本；保留 manifest、admission/登记回执、独有项和失败续跑点 |
| 多次渲染各带一套图片、音频、字体 | 查素材锁、打包清单、渲染入口和交付工程，区分运行时从源目录取用还是包内自带 | 已结束尝试的重复素材；仍需原路径的静态副本评估共享块，字体及其他未受支持类型按下文边界处理 |
| 构建失败后留下完整源码或依赖树 | 查失败发生在哪一阶段、是否有唯一改动、恢复 ref、锁/租约和本次开机时间；全量逐文件与可恢复提交核对 | 精确匹配的候选文件；保留差异、回执和 Git 登记，失败本身不证明整树可删 |
| 父会话、子 Agent、exec 历史和数据库同时增长 | 区分存储文件、索引及原生数据库分页占用，核对父子关系、归档、最后一轮与任务交付 | 按原生删除命令的真实连带范围处理；数据库压缩/回收另计，不能用删除日志体积代替数据库实测 |
| 多轮安装维护备份和退休归档并存 | 查回滚说明、现役入口、旧版本与当前版本的差异，找完整相同文件及仍需保留的配置 | 保留一份可用回滚来源后，逐文件提出重复副本候选；不把旧配置、补丁或零字节新版本当已替代 |

阶段关闭证据优先取交付回执与正式消费者状态，旧 README 中的“待完成”要和后续结果对照。已结案的旧回放脚本若仍指向过程目录，记录它的真实用途、退休依据与恢复入口；不能直接写成“无引用”。

字体是典型共享输入：先识别系统已安装字体、授权随包分发字体和任务内复制件。当前 APFS 共享块方法不处理安装字体；其余字体也须确认现有执行器支持，不能因内容相同就套用媒体命令。生产器后续可引用既有共享素材或按需装配，但修改路径属于独立变更，不能混入普通删除。

## 区分真实消费者与历史路径

从当前启动命令、队列/租约、续跑入口、正式 manifest、发布器和交接要求反向追踪。引用核查同时覆盖受跟踪代码与已定位的未跟踪调度副本；只查 `git grep` 会漏掉 Agent 复制出来的 REGISTER、runner 和一次性脚本。

- 脚本实际读取、续跑需要、当前 manifest 引用：保留。
- 历史审计叙述或明确排除该目录的条件：记录具体语义和证据，可按既有 history_only 流程复核。
- 一组旧脚本互相引用：继续追到是否仍有有效入口，不能仅凭互引宣称仍在用，也不能仅凭无进程宣布整组退役。
- 路径是下一次运行会重新初始化的工作区：核实初始化与失败保留契约；可再生本身不等于可删除。

不自动放宽 24 小时、受保护项目、活动进程、唯一证据等闸门。需要新的阶段证明类型时，先实现窄适配器及拒绝反例，再接现有校验和执行器，不修改父项目状态或绕过 profile。

## 跨重启遗留的初始化构建树

Git `locked initializing` 且无 index 的旧目录可能是中断检出；status 的大量删除/未跟踪不能据此认定是用户编辑。先核锁与本次开机时间、租约、打开文件、源提交和全部文件内容。缺租约不等于空闲。

`scripts/retired_worktree.py plan/check` 是只读证明工具，仅支持受管临时构建命名空间及其明确初始化形态。调用前保留指向原 HEAD 的恢复 ref；plan 输出精确匹配文件、必须保留的差异和 seal，check 重验全部指纹、内容、目录、锁和恢复 ref。

它不删除、不解锁、不修改工作树登记，也不授予删除权限。只有证明中的精确匹配普通文件可转为现有 `scope=files` 计划；保留 `.git`、锁、登记及所有差异。随后仍经过引用、项目、保护、check/seal、dry-run、pilot/run。条目使用 `checkpoint={kind:"retired_build_copy", proof:"绝对证明文件路径", seal:"完整摘要"}`。校验与每次执行重新验证本批所选文件、锁、恢复 ref 和活动状态；前批已删的未选文件不影响后批，额外未选文件继续保留。改变所选文件或证明会拒绝。普通工作树与长期战役树不适用这个入口。

## 已完成登记阶段的重复暂存库

`scripts/registered_stage_checkpoint.py` 支持 `kind:"registered_stage_copy"`：正式 manifest 仍登记相同四类文件、正式实体逐 SHA256 一致、登记 PASS 与计数一致、完成回执绑定候选提交中的同份 manifest 时，才证明该登记子阶段的副本可清。父项目仍可继续，不能把阶段完成改写成整项目发布。

证明同时固定 owner_repo、formal_root、stage_manifest、formal_manifest、receipt、adoption 与必要消费者证据及各自 SHA256。只接受显式 `scope=files` 普通文件；保留 manifest、全部回执、正式库和未选差异。一个 stage 一个 item，执行前要求整组原始库存完整，因此不要跨 item 拆分同组。正式 manifest 漂移、丢失成员、阶段缺证、活动消费者或新修改均暂停，不扩大允许范围。

逐文件清单的保留依赖检查按真正选中的文件判断；若其他卡选中回执或整个保留目录，仍拒绝，不能因回执与废弃副本同目录就误报整目录将删除。

## 会话历史单独计账

按父任务汇总交互记录、子 Agent、批量 exec、生成图和分页历史库，说明哪些计量可能重叠。官方原生压缩已完成的日志不能再按未压缩字节估计收益。最后一轮 completed、未归档、无进程分别只是事实；不据此删除整段交互历史。原生命令的后代连带范围与数据库回收见 Codex 知识卡。

## 从源头减少积累

结束阶段的回执应列出保留输入、正式输出、必要检查点、废弃过程件，以及下次如何恢复。正常退出清理和异常退出后的恢复清理都要有真实入口；`finally` 不能处理断电或强杀。默认在下一次受管启动或用户清理时核验遗留现场，不额外安装后台常驻程序。

修改生产器后核对实际调用的版本：主脚本修好不代表历史复制脚本已更新。定制副本不能盲目覆盖，应迁移共享生命周期逻辑并验证原有功能。清理失败要检查退出码及目录实际存在性，不能只打印“成功”。

按本机观察提出常驻工作集、单任务峰值和并发余量建议；目标空余容量不是扩大删除权限的依据。稳定个人边界沿用私有配置，具体任务证据留账本，不不断追加全局记忆。每次交付报告“已释放、待决策、证据不足、仍在生产”各自的具体对象和体积。
