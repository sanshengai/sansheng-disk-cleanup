# 为什么手工扫描赢了 Skill（2026-10-26 对比实验）与固化的修正

同一台 Mac、同一时刻：Skill 全流程 704 秒（遍历 85 + 引用检查 590），**可直接删 0 项**；手工 du+lsof+git 约 9 分钟，稳妥可回收 ≈90G（4 个已合并 worktree 74G + 缓存 16G）+ 旧发布 6G。

## 根因（按影响排序）

1. **默认判定方向反了**：Skill 以“证明已完成 + 引用检查”为放行前提，缺证据一律“需确认”→ 0 项可删。手工靠“类别本身可再生 + 无进程打开 + 近期无写入”就能判。缺一个“可再生缓存白名单”档。
2. **最大回收源无出路**：整仓 worktree 内容全是 git 跟踪文件，“跟踪文件不删、不 worktree remove”规则下永远出不了卡（今天 80G）。手工用 locked / status / lsof / merge-base 四个信号就能给 `git worktree remove`。
3. **阈值 + 只列大目录**：500MB 门槛只记大目录，覆盖率 66.6%，可再生缓存长尾全漏：`$TMPDIR` node-compile-cache 5.7G、hyperframes-extract-cache 4.4G、c7-input 1.4G、`~/Library/Caches` 4.7G、`~/.npm`、`~/.cache/uv`、codex-runtime-install-*。这些位置写在 agent-junk-locations 卡里，却没有被脚本直查。
4. **引用检查贵且无判断力**：worktree/成品目录引用数几千，590 秒只换来“引用很多”；超时节点静默记为“引用未查”。lsof、mtime、git status、merge-base 便宜又准。
5. **工具坑**：PATH 里是 GNU coreutils，`stat -f %l` 报错 → 一律 `/usr/bin/stat`；同理 sed 用 `/usr/bin/sed`；`$TMPDIR` 带结尾 `/`。
6. **增长对比误导**：① 上次未单列的新目录进 unmeasured、不计入合计（最大的 80G 新 worktree 被藏）；② “已用”取 `总量−可用`（容器口径，含快照/其他卷/可清除空间，且被并行清理影响），与 df 的本卷已用（462→593G）方向都相反；基准记录里没有 df 口径时应说“无可比基线”。
7. **全量遍历慢**：单线程自顶向下走到 depth 10。手工是并行 `du -d` 先宽后深，找最大再深挖。
8. **其他手工有、Skill 没有的发现**：工作仓 `.git` 当天新写 11G pack（repack 残留，应给 `git count-objects -vH` 建议）；构建暂存 slot2 29G（扫描时在用）；releases 旧版只留最近一次；codex thread_history sqlite 16G（只能原生回收）；517 处无权限未覆盖应明确列出。
9. **默认写家目录**：scan 默认写 `~/.sansheng`，只读体检也会落盘。

## 已固化的修正

- 新入口 `scripts/triage.py`（只读，默认 /tmp）：并行 du 先宽后深 + 白名单直查 + 一次 lsof 快照 + find -mmin + git status/merge-base；分 1/2/3 档 + 保留，附命令卡。
- `space_history.py`：新出现目录计入合计并单列；记录 df 口径并报“已列出合计 vs df 变化”差额；无 df 基线时明说。
- `scan.py`：`--read-only`（runs 落 /tmp，只读家目录历史作基准）；大 git 树跳过引用扫描；汇总列出“引用未查”目录。

## 2026-11 第二轮对比的新增根因与修正

1. **成品目录一刀切保护**：成品目录在 HARD_KEEP 里整体保护，几十 GB 的试做、v1–v3、旧版、`.作废` 目录从不出现在任何清单，手工却能逐个指出。修正：整体仍保护，但第二层逐项列“需用户判断的成品清单”（大小/最近写入/引用数/命名分类），不出删除命令。
2. **缓存规则不统一**：triage 用 6 小时、卡片写 24 小时，同一目录两处结论不同。修正：SKILL.md「第 1 档统一规则」唯一出处，卡片更严时取较严者。
3. **固定位置没覆盖**：`$TMPDIR/pytest-of-*`、与 `$TMPDIR` 同级的 `X/com.google.Chrome.code_sign_clone`、`~/Library/Caches/Google`、`~/Library/Caches/baoyu-skills`、Skill 自己的 `~/.sansheng/disk-cleanup` 都由手工发现。已补进 triage 与 agent-junk-locations 卡。
4. **命令与硬约束矛盾**：第 1 档曾输出 `rm -rf`，与“不得用 rm -rf”冲突；检查与删除也混在一条。修正：原生命令优先，其余 `find -x DIR -mindepth 1 -delete`，检查命令单独一条。
5. **运行中 App 的缓存被列进一键清单**：CodexBar、cmux、Chrome 等在跑时删缓存会被立刻重建或出错。修正：识别进程，移到“待 App 退出后”。
6. **增长对账解释反了**：差额为负时仍说“小增长与未扫区域”。修正：负 = 已列增长之外有删除抵消；正 = 小增长与未扫区域；有单测。
7. **df 口径下了未证实的结论**：上一版把 GNU df 多出的约 30 GiB 归因于“~ 映射到系统快照卷”，实测反驳。修正：只陈述事实，统一 `/bin/df`、GiB；scan.py 十进制 GB 明确标注；pack 与整个 .git 分开写。

## 知识卡：会反复出现的增长源

- **Agent 每次修复都新建整仓 worktree**：每个约 20G，10/9 与 10/25 两次各 +80G 级。建议 Agent 用稀疏检出（`git sparse-checkout`/`--no-checkout`）或共享主仓，合并后立刻 `git worktree remove`。
- **清理存档放同一块盘会抵消回收**：cleanup-archive-* 打包在本盘，等于没腾空间。存档应搬到外接盘，或提醒用户；搬走前它属于“保留”。

## 2026-11-03 第三轮对比的新增根因与修正

同一台 Mac、同一时刻：Skill（triage 592s + scan 535s）**可直接删 0 B**，第 3 档 74.7 GiB 待判断；手工约 15 分钟。用户按手工清单授权后实际处置：删除 150.6 GiB（条目核算）+ 克隆去重 31.7 GiB 名义 / 16.6 GiB 实测 + Codex 生图上云后删 5.2 GiB，可用空间 295 → 约 445 GiB。手工也有一处判错（把两个“已恢复”的 tgz 当双份），被 Skill 的逐文件比对纠正——这一条 Skill 赢。

1. **“在用”按整目录判**：Chrome 克隆目录 5 份只开 1 份，整个 7.1G 判在用；缓存目录同理。→ 整目录不过时拆到子项逐个判；Chrome 克隆按运行中主进程的启动时刻逐份匹配，同版本残留也可清（`chrome_clones.py` 原来只清旧版本）。
2. **引用检查被历史记录污染**：快照比对清单、本 Skill 往期 triage.json、前后对照 json 都算“引用”，读书蒸馏、文稿成品、家人健康资料全成了“被引用”。反过来真正读路径的脚本根本不在搜索范围。→ 搜索加脚本与 SKILL.md；命中分“消费者 / 历史记录”，只有消费者拦截。
3. **从不查重复副本**：同一批成片在 成品库/交付/分发暂存/工作树 各一份，≥20MB 的重复 42G。→ triage 抽样哈希出报告；新增 `clone_dedupe.py` 用 APFS 克隆原地去重，不删任何路径（交付目录、发布流水线照常可用）。
4. **活跃的长期工作树一刀切保留**：103G 的树里 73G 是 10 月中下旬停写的旧季过程件。另有一个静默 bug：被忽略体积用了 `git status --ignored=matching --untracked-files=no`，这对参数在当前 git 是非法组合，git fatal、输出为空，报告写“被忽略 0 B”（实际 20G+）。→ 改用 `git ls-files --others --ignored --directory` 并检查退出码；新增“停写的旧子任务”，给 `git clean -x` 预览/删除命令卡。
5. **成品清单只到第二层、分类先看名字**：第五层的 `.作废-重叠`（3.2G、0 引用）看不见；今天还在写的“历史英语试播”因名字含“试播”被归进旧版。→ 任意深度找作废目录；先看 24 小时写入再看名字。
6. **同盘存档死循环**：26G 存档按路径名硬保护，只能“建议搬外接盘”，而这一步从没人做。→ 规则改为禁止往本盘归档；盘外有同路径同大小副本的给“本地可删”命令卡。
7. **慢**：存档核对每个 tgz 跑一次 `find <工作区> -maxdepth 5`，26 个包占 350/592 秒。→ 整轮只建一次目录索引。
8. **瞬时目录记成增长**：扫描中出现又消失的 App 内容快照（7.2G）被列为“新出现的大目录 / 未归类”。→ 收尾复查存在性，消失的单列为临时产物、不计入合计。
9. **测试依赖本机状态**：`space_history.make()` 对“不在家目录 runs 下”的任意运行目录都去读本机真实历史，测试在有历史的机器上失败。→ 只对只读体检的固定运行目录这样做。
