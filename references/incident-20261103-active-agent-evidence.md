# 复盘：整批授权后删掉了另一个 Agent 还在用的原始素材（2026-11-03）

## 经过

用户在对话里整批授权：“低风险的直接删，证据充分的全部删，长期工作树里的旧过程文件全部删”。执行清理的 Agent 自己判断了清单，用一个临时脚本逐项删除。其中一项是长期工作树里一个旧阶段目录的未跟踪文件（约 42 GiB）。判断依据是这个目录 7 天没有写入，网盘备份台账里也有这些文件。

当天下午，另一个 Agent 在同一条产品线上做新阶段的准备，合回时被门禁拦下。门禁会校验旧阶段的历史证据：几百份证据要求原始素材文件逐字节存在，其中 18 份刚被删了。那个 Agent 查不到是谁删的（废纸篓里没有），只好在交接文档里写“删除者未查明”，把问题交给用户拍板。

## 漏掉的检查

1. **引用检查只搜了文档，没搜代码和门禁登记。** 门禁登记文件和校验脚本按“仓库相对路径”引用这个目录，但临时脚本搜的是“工作区相对路径”（工作树的路径前面多一段），所以没有命中。
2. **没看这条线当天有没有人在干活。** 这个目录当天中午就有新提交；其他 Agent 近 72 小时的对话里，有一百多个会话提到它。
3. **没看目录里有没有已跟踪的脚本。** 目录里有 20 个已跟踪的生产和校验脚本，未跟踪的素材正是它们的输入和证据。“Git 不管”不等于“没人用”。
4. **“没有写入”不等于“没有人读”。** 证据文件只会被读，不会被写，所以静默期检查拦不住。
5. **没有备份的过程件直接删了，没有先隔离。** 这次碰巧都有网盘备份，所以能恢复；如果没有，就只剩这一份。
6. **清理日志别的 Agent 找不到。** 日志写了，但共享规则里没告诉其他 Agent“文件不见了先查清理日志”。

## 改了什么

- 新增已授权清单执行器 `scripts/quick_act.py`。整批授权时不再临时写脚本，上面 1–3 条都变成删前的强制检查：
  - 代码与配置引用，包括仓库相对路径；
  - 该路径近 7 天的提交；
  - 其他 Agent 近 72 小时的对话记录；
  - 所在目录里的已跟踪脚本。

  任一命中都要用户在原话里写出目录名才放行，“全部删”不覆盖它们。拿这次的目录回放，执行器会拒绝，并列出门禁登记、20 个脚本、当天的提交和 144 个会话。
- 没有盘外备份的过程件只改名隔离 7 天（红线 6 原来是手工步骤，现在由脚本强制执行）；有备份的逐文件核对，并抽样回读。
- 红线第 5 条补充：把“文件不见了先查清理日志”写进共享规则；新增红线第 8 条“别的 Agent 还在用的不删”。

## 给人的启示

整批授权省掉了逐项确认，也把“这条线现在有没有人在用”这个问题交给了 Agent。Agent 看得到文件和引用，但看不到别的会话正在干什么，除非去查提交记录和对话记录。所以这一步必须由机器强制执行，而且要放在执行瞬间，不能靠 Agent 自觉。
